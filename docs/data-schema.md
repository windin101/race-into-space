# Game data schema

Everything under `game/data/` is generated by `tools/import_upstream.py` from the upstream
GPL port's `data/gamedata/*.json`, except `constants.json`, which is transcribed by hand
from the port's C++ (see `docs/specs/code-derived-rules.md`). Regenerate with:

```
python3 -I tools/import_upstream.py --upstream reference/raceintospace --out game/data
python3 -I tools/validate_against_manual.py --data game/data
```

Every file has a `_source` block (upstream project, git revision, source files) and most
have a `_notes` block explaining fields. All numbers are integers; the Godot loader
(`game/scripts/data/game_data.gd`, autoload `GameData`) converts the parser's floats back
to ints.

## hardware.json

```
models.{basic|historical}.{usa|ussr}.{probe|rocket|manned|misc}[7]
```

Seven fixed slots per group, `null` for an empty or unavailable slot. Slot order matters:
the upstream engine addresses hardware by slot, and the mission tables reference it.

| slot | probe | rocket | manned | misc |
|---|---|---|---|---|
| 0 | Explorer / Sputnik | Atlas / R-7 | Mercury / Vostok | Kicker-A |
| 1 | Ranger / Cosmos | Titan / Proton | Gemini / Voskhod | Kicker-B |
| 2 | Surveyor / Luna | Saturn / N1 | Apollo / Soyuz | Kicker-C (USSR only in Historical) |
| 3 | | Nova / UR-700 | XMS-2 / Lapot | EVA Suits |
| 4 | | Boosters | Jupiter / LK-700 | Docking Module |
| 5 | | | Eagle / LKM (LM) | Photo Recon |
| 6 | | | Cricket / LK (LM) | |

Record fields: `slot`, `name`, `base_safety`, `program_cost`, `unit_cost`,
`rd_cost_per_team`, `unit_weight`, `max_payload` (rockets), `max_rd`, `max_safety`,
`max_days` (capsules and LMs only).

The Basic model is symmetric: both sides have identical numbers. The Historical model
makes the US dearer and more reliable. The Random model has no data file; it is generated
at new-game time (rules in `constants.json` once transcribed).

## prestige.json

`rows[28]`: `index`, `key` (snake_case id used in code), `title`, `first`, `second`,
`other`, `failure`. Row order is the upstream `Prestige_*` enum; `missions[].prestige_categories`
indexes into it.

## missions.json

`missions[62]`, position equals `index`. Fields:

- `name`, `abbr`
- `code`: step string. One letter per step; `+n` switches to launch vehicle n of a joint
  mission (rescue missions use `+4`); `!` marks the end of the normal sequence; `|` terminates. Letter meanings
  live in `constants.json` under `step_letters`.
- `alt[36]`, `alt_d[36]`: per-step alternate/abort step index (-1 none, -2 continue, -3 end).
- `days`: duration level required, 0 none, 1 to 6 for A to F.
- `dur`, `docking`, `eva`, `lm`, `joint`, `lunar`: 0/1 flags for what the mission involves.
- `m_eq`: equipment-class code, `m_vab[2]`: VAB illustration ids (upstream art, unused here).
- `crew_mode`: 0 unmanned, 1 unmanned with capsule, 2 single-pad manned, 3 joint with one
  manned launch, 4 joint with two manned launches, 5 joint with unmanned capsule. Crew
  head counts come from the capsule's capacity in `constants.json` (`crew.capacity_by_hardware`).
- `prestige_categories`: up to five prestige row indices this mission can claim.
- `lm_ad`: LM-related flag (confirm in constants).
- `downgrades`: ordered mission indices to fall back to when hardware is missing; `0` ends the list.
- `diagram`: Future Missions bubble-diagram tokens from upstream `missSteps.json`.

## failures.json

`failures[925]`: `step` (F000.. codes), `percentage` (roll band, -1 default), `code`,
`val`, `xtra`, `fail` (outcome ids) and `text`. Semantics of the numeric fields are in
`constants.json` under `failure_codes`. Text is upstream prose and will be rewritten
before release (Phase 7).

## roster.json

`sides.{usa|ussr}[5]` recruitment groups: `group`, `number_to_choose`, `recruiting_delay`
(seasons; 99 never), `candidates[]` with `name` (upper case as upstream), `female`, `race`,
`service` (0 civilian, 1 to 3 branch), and skills `capsule`, `lm`, `eva`, `docking`,
`endurance` (0 to 4). 224 candidates in all, 112 per side.

## budget_adjustments.json

The upstream 180-int newscast budget table, as `flat[180]` and `blocks[3][6][10]`
(3 blocks x 6 budget bands x 10 picks). Indexing is confirmed in `constants.json`.

## new_game.json

Start year and season, each side's default director name and starting budget (60 MB),
default difficulty and astronaut-data level.

## text/

| file | contents |
|---|---|
| `events.json` | 117 newscast events per side, each `{text, color}` (0 neutral, 1 good, 2 bad) |
| `news.json` | astronaut filler news, retirement reasons, general filler news per side |
| `reviews.json` | 36 annual review lines, indexed by outcome |
| `endgame.json` | 12 end-of-game narrations |
| `help.json` | 289 help entries, raw lines with upstream layout directives |

All text has upstream `*` line breaks converted to `\n` and the `x` terminators stripped.
It is upstream prose under GPL and is a placeholder: Phase 7 replaces it with new writing.

## constants.json

Hand-transcribed rules that exist only in the upstream C++: prestige row names, duration
day bands, crew capacities, milestone and penalty values, rush costs, budget formula,
difficulty effects, R&D roll, step-letter semantics, failure-code semantics, personnel
rules and the calendar. Each key carries a `source` with the upstream file and line.

## Known discrepancies

- Docking module max safety: manual says 98%, reference card and upstream say 93/94%. Upstream used.
- XMS-2 / Lapot `max_days` is 15 in upstream; the manual's duration table caps them at level D (8 to 12 days).
- Roster names: upstream `crew.json` and `roster.json` differ on three transliterations
  (Gubaryev/Gubarev, Kovalyonok/Kovalyanok, Peterson/Petersen). `roster.json` is used.
